# Telegram Web Proxy Wizard

[English](README.md) · توسعه و نگهداری: **sinascorpion**

نصب آسان و ویزاردی پروکسی وب تلگرام با HTTPS و تمدید خودکار گواهی، انتخاب CDN،
تگ اختیاری اسپانسر و فرمان حذف کامل.

## نصب با یک فرمان

یک سرور اختصاصی اوبونتو آماده کن؛ نسخهٔ پیشنهادی **24.04** است. دامنه یا ساب‌دامنه
و دسترسی root لازم است. پورت ۸۰ برای دریافت و تمدید گواهی باز باشد و SSH را باز نگه دار.

```bash
curl -fsSLo /tmp/telegram-web-proxy-install.sh https://raw.githubusercontent.com/sinascorpion/telegram-web-proxy/main/install.sh && sudo bash /tmp/telegram-web-proxy-install.sh
```

دستور نصب، منوی مدیریت را باز می‌کند؛ برای نصب گزینهٔ **۱** را انتخاب کن.
ویزارد دامنه، ایمیل اختیاری گواهی، تگ اسپانسر، سکرت قبلی، حالت CDN و پورت HTTPS سرور مبدأ را
می‌پرسد. حالت‌ها `none` برای اتصال مستقیم، `cloudflare` و `other` برای CDNهای دیگر
هستند. پورت پیش‌فرض سرور ۴۴۳ است. برای صدور اولیهٔ ساده‌تر، DNS را موقتاً مستقیم
به سرور وصل کن؛ پشت CDN هم در صورت عبور صحیح درخواست HTTP-01 امکان صدور وجود دارد.

## انتقال به سرور جدید با حفظ لینک کاربران

قبل از ازدست‌رفتن سرور، دامنه و سکرت لینک `mtproxy-web link` را جای امن نگه دار.
روی سرور جدید همان دامنه و سکرت قبلی را در ویزارد وارد کن. سکرت خام ۳۲ کاراکتری
یا مقدار کامل `dd` به‌اضافهٔ ۳۲ کاراکتر هگز از لینک این نصب‌کننده پذیرفته می‌شود.
ورودی مخفی است. Enter روی نصب موجود سکرت را حفظ می‌کند و در نصب تازه سکرت می‌سازد.

DNS یا آدرس مبدأ CDN را به سرور جدید تغییر بده و تنظیمات پورت و مسیر CDN را مشابه
قبل تنظیم کن. با دامنه و سکرت `dd` یکسان، لینک Web Proxy دقیقاً یکسان می‌ماند و کاربران
نیازی به افزودن لینک تازه ندارند؛ فقط اتصال‌های فعال دوباره برقرار می‌شوند. گواهی
معتبر تازه خودکار صادر می‌شود و نیازی به کپی کلید SSL قبلی نیست. IP مبدأ باید IP
جدید باشد. تنظیماتی مثل تگ اسپانسر را هم در صورت نیاز دوباره وارد کن.

این قابلیت برای لینک Web Proxy نوع `dd` این نصب‌کننده است؛ سکرت FakeTLS با پیشوند
`ee` یا نوع لینک و مسیر متفاوت جایگزین آن نیست. سکرت گم‌شده از روی دامنه قابل بازیابی نیست.

## CDNهای دیگر

کارکرد به کلودفلر محدود نیست. ارائه‌دهندهٔ دیگر، از جمله Fastly یا آروان، باید روی
سرویس و پلن انتخابی تو این نیازها را برآورده کند: HTTPS معتبر روی پورت عمومی ۴۴۳،
TLS معتبر تا سرور، عبور بدون تغییر Host و مسیر و هدرهای احراز هویت، درخواست‌های
POST و DELETE، long polling و WebSocket. حالت HTTPS چندمسیره به HTTP/2 نیاز دارد.
کش، چالش جاوااسکریپت، CAPTCHA، صفحهٔ ورود و تغییر محتوای صفحه باید برای دامنه غیرفعال باشند.

پس صرف بازبودن پورت کافی نیست. ممکن است فعال‌سازی WebSocket یا پلن مناسب جداگانه
لازم باشد. کلودفلر تست عملی شده است؛ سازگاری همهٔ پلن‌های سایر ارائه‌دهندگان ادعا نمی‌شود.

در حالت کلودفلر، رنج‌های رسمی به‌صورت خودکار دریافت می‌شوند و فقط هدر IP از همان
رنج‌ها پذیرفته می‌شود. SSL را روی Full (strict) بگذار. در حالت `other` به‌طور پیش‌فرض
به هیچ هدر IP اعتماد نمی‌شود؛ ترافیک عبور می‌کند، اما شمارش IP، آدرس لبهٔ CDN را می‌بیند.
برای IP واقعی کاربر، رنج‌های رسمی و هدر معتبر همان ارائه‌دهنده را در ویزارد یا با
`--trusted-proxy-cidr` و `--client-ip-header` وارد کن. برای پاک‌کردن رنج‌ها `-` وارد کن.

## پورت‌های ۲۰۸۳، ۲۰۹۶، ۲۰۵۳ و مشابه

کلاینت فعلی Telegram Desktop برای Web Proxy، **پورت عمومی ۴۴۳ را ثابت کرده است**.
قرار دادن `:2083` یا پورت دیگر در لینک، این محدودیت را تغییر نمی‌دهد.

اما می‌توان پورت HTTPS روی **سرور مبدأ** را تغییر داد:

```bash
sudo mtproxy-web configure --non-interactive --cdn-provider other --origin-port 2083
```

سپس باید در پنل CDN، مسیر **۴۴۳ عمومی به ۲۰۸۳ سرور مبدأ** را تنظیم کنی؛ Host و TLS SNI
باید همان دامنه بمانند. امکان این نگاشت به ارائه‌دهنده و پلن بستگی دارد و نصب‌کننده
به حساب CDN تو دسترسی ندارد. لینک تلگرام همچنان بدون پورت باقی می‌ماند.

پورت‌های مبدأ مانند ۲۰۵۳، ۲۰۸۷، ۲۰۹۶ و ۸۴۴۳ هم قابل تنظیم‌اند. اینکه کلودفلر روی
این پورت‌ها HTTPS را می‌پذیرد، محدودیت پورت کلاینت تلگرام را برنمی‌دارد. برای اتصال
مستقیم بدون CDN فقط ۴۴۳ مجاز است. پورت ۸۰ همچنان برای تمدید HTTP-01 باز بماند.

## مدیریت و اسپانسر

بعد از اولین نصب، هر زمان این فرمان را بزنی منوی کامل مدیریت باز می‌شود:

```bash
sinascorpion-webproxy
```

اگر با کاربر root نیستی، `sudo sinascorpion-webproxy` را اجرا کن. این فرمان پس از
نصب هم به کاربر نمایش داده می‌شود. برای نصب‌های قبلی، دستور تک‌خطی را دوباره اجرا
کن و نصب یا نصب مجدد را انتخاب کن تا فرمان مدیریت اضافه شود.

منو شامل نصب یا نصب مجدد، ویزارد تنظیمات، تغییر دامنه، تغییر سکرت، غیرفعال‌سازی،
فعال‌سازی مجدد، وضعیت، نمایش لینک و حذف است. نصب مجدد، هسته را دوباره دریافت می‌کند
و دامنه و سکرت را نگه می‌دارد. برای تغییر دامنه، DNS/CDN دامنهٔ جدید را آماده کن؛
ابتدا گواهی تازه دریافت می‌شود و اگر فعال‌سازی شکست بخورد، تنظیمات قبلی برمی‌گردد.
تغییر دامنه یا سکرت، لینک کاربران را تغییر می‌دهد.

غیرفعال‌سازی، سرویس پروکسی و اجرای خودکار آن و مسیر عمومی HTTPS پروکسی را متوقف
می‌کند؛ تنظیمات و گواهی حفظ می‌شوند. فقط مسیر HTTP-01 برای تمدید گواهی باقی می‌ماند.
فعال‌سازی، پروکسی را برمی‌گرداند. تغییر تنظیمات در حالت غیرفعال، خودکار آن را فعال نمی‌کند؛
نصب یا نصب مجدد آن را فعال می‌کند.

حذف از داخل منو قابل انتخاب است. می‌توان بسته‌های اضافه‌شده را هم پاک کرد و انتخاب
کرد که فرمان مدیریت باقی بماند یا حذف شود. پیش‌فرض، نگه‌داشتن فرمان مدیریت برای نصب
بعدی است؛ برای حذف همه‌چیز از جمله فرمان مدیریت، گزینهٔ مربوط را تأیید کن.

گواهی SSL و کلید خصوصی آن به‌صورت پیش‌فرض هنگام حذف حفظ می‌شوند تا نصب دوباره روی
همان دامنه به صدور جدید نیاز نداشته باشد. تمدید در زمان حذف متوقف و هنگام نصب دوباره
فعال می‌شود. گواهی باید منقضی نشده باشد، دامنه را پوشش دهد و کلید خصوصی درست داشته
باشد. تغییر سکرت به SSL جدید نیاز ندارد. برای گواهی منقضی، مفقود یا غیرقابل‌استفاده،
صدور یا تمدید لازم است. برای حذف گواهی هم، گزینهٔ مربوط در منو یا
`--delete-certificate` را انتخاب کن. استفادهٔ مجدد مربوط به گواهی‌های مدیریت‌شده
توسط همین نصب‌کننده است؛ گواهی برنامه‌های دیگر بازنویسی نمی‌شود.

```bash
sudo sinascorpion-webproxy configure
sudo sinascorpion-webproxy change-domain
sudo sinascorpion-webproxy change-secret
sudo sinascorpion-webproxy disable
sudo sinascorpion-webproxy enable
sudo sinascorpion-webproxy link
sudo sinascorpion-webproxy status
sudo certbot renew --dry-run --no-random-sleep-on-renew
sudo sinascorpion-webproxy uninstall --purge-dependencies --remove-manager
sudo sinascorpion-webproxy uninstall --purge-dependencies --remove-manager --delete-certificate
```

فرمان قبلی `mtproxy-web` هم برای سازگاری حفظ شده است.
برای کانال اسپانسر، از [@MTProxybot](https://t.me/MTProxybot) تگ هگز ۳۲ کاراکتری
بگیر و در ویزارد وارد کن. نام کانال کافی نیست. با تگ، اتصال middle proxy فعال
می‌شود؛ نمایش واقعی کانال به ثبت معتبر ربات و رفتار تلگرام وابسته است. بدون تگ واقعی
نمی‌توان نمایش اسپانسر را تأیید کرد. برای حذف تگ، `-` وارد کن.

سکرت و گواهی هنگام تغییر تنظیمات حفظ می‌شوند. حذف کامل فقط داده‌ها و بسته‌های
اضافه‌شده توسط نصب‌کننده را پاک می‌کند؛ SSH و فایروال دست‌نخورده می‌مانند.
نسخهٔ تلگرام باید از لینک `tg://webproxy` پشتیبانی کند.

## چند سکرت و فیلترینگ

سکرت جدا برای هر کاربر به مدیریت دسترسی کمک می‌کند؛ اگر یکی لو رفت، می‌توان همان
را تعویض یا حذف کرد بدون اینکه بقیه نیازمند سکرت تازه شوند. اما همهٔ سکرت‌های روی
یک دامنه یا IP، همان نقطهٔ اتصال عمومی را دارند؛ مسدودشدن آن نقطه روی همه اثر می‌گذارد.
پس چند سکرت به‌تنهایی مانع فیلترشدن دامنه یا IP نیست. این نصب‌کننده فعلاً یک سکرت
مشترک را مدیریت می‌کند و تغییر آن، لینک‌های قبلی را نامعتبر می‌کند.

گزارش تست در [TESTING.md](TESTING.md) و مجوز وابستگی در [NOTICE.md](NOTICE.md) آمده است.
